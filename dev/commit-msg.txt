Two more real bugs, both found by the Linux run

schtasks: sensorsetup._schtasks ran the Windows Task Scheduler executable with no
platform guard. Off Windows the binary does not exist, so subprocess raises
FileNotFoundError instead of returning a failure, and every caller - create,
delete, query, run - was written to expect a (code, message) pair. It now returns
one on either platform, and task_action does not go looking for a scheduler that is
not there.

-toolwindow: the summary window set a Windows-only Tk attribute. Tk on X11 rejects
it with "bad attribute", and the line only means "this is a normal window, not a
palette" - which is the default elsewhere, so it is now applied where it exists and
skipped where it does not.

Both are the kind of thing no amount of reading finds and one run on the real
platform does. Windows suite still green: 39 files, 0 failures.
