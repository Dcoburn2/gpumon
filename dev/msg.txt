1.0.6: the Linux build, and the Windows-only calls it found

The Linux half of the program has existed since the port and had never once been
executed: sysfs for AMD cards, rocm-smi, Intel GPUs, /sys/class/thermal and hwmon
for CPU temperature, a shell launcher, the terminal and browser interfaces, all
written against fixtures. A new workflow runs the suite and builds a tarball on
ubuntu-latest, and attaching it to the release is what this tag is for.

Getting it green took seven runs, and every fix but the last two was a real defect
that only running on the platform could reveal:

  * creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0) - the fallback makes
    the value zero, but subprocess rejects the keyword outright on POSIX, so
    anything that spawned a process failed
  * schtasks, run with no platform guard: FileNotFoundError where the executable
    does not exist, rather than the (code, message) pair every caller expects
  * ctypes.WinDLL("kernel32") at import time in three modules, which makes them
    unimportable rather than merely unusable
  * a Windows-only Tk attribute, -toolwindow, rejected by Tk on X11
  * two backends that reported nothing when unavailable, so a missing sensor could
    not be told apart from one that looked and found nothing
  * no CPU-temperature note on Linux at all, because the explanation was written
    inside the Windows notes

The rest was the suite being about Windows where it should have been about the
platform: the .cmd launcher, the registry shortcut lookup, LibreHardwareMonitor's
backends, a signing stub, and an assertion that the platform is Windows.

Windows suite green at 40 files and 0 failures, Linux suite green, and the Linux
binary builds, starts and passes its own self-test - the first time this program has
run on Linux at all.
